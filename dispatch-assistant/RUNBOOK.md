# 调度助手运行手册

## 目标

为客户、仓库、国内调度和工厂四方建立一个可追溯的出货协调流程。当前阶段只读取、分析和生成草稿，任何微信、邮件、预约或文件都不自动对外发送。

## 信息优先级

出现冲突时按以下顺序处理：

1. 客户最新书面确认及最新 Delivery 文件。
2. 前一天再次确认的客户回复。
3. 仓库/工厂最新明确的备货完成时间。
4. 客户初步计划文件。
5. 微信中的口头计划或未确认变更。

不覆盖冲突记录；报告中同时列出原值、新值、来源、时间和待确认人。

## 状态流转

`Initial Plan` → `Warehouse ETA Pending` → `Ready Date Known` → `Customer Initial OK` → `T-1 Reconfirmation Sent` → `Customer Second OK` → `Final Confirmed / Released`

异常状态包括：`Factory Pickup Required`、`Schedule Change Pending`、`Blocked`、`Source Unverified`。

只有客户在送货前一天再次回复 OK，才进入 `Final Confirmed / Released`。第一次 OK 只是暂定确认。

## 每日早班（06:00 ET）

1. 扫描新附件，但不将微信附件目录等同于“库房”来源。
2. 只读打开微信并定位名称完全等于“库房”的群聊；禁止读取其他聊天。
3. 汇总今天、明天和未来 7 天的 PO、时间、备货状态、工厂提货需求、客户确认阶段和风险。
4. 生成给仓库的微信群草稿、需要联系工厂的提货邮件草稿、需要联系客户的邮件草稿。
5. 若微信读取失败，继续处理已登记正式文件，并明确列出“微信文字未读取”和需要人工提供的截图/转发。

## 前一天复核（每日 15:00 ET）

1. 找出明天所有计划送货的 PO；周末也必须执行。
2. 核对 Delivery 文件、最新变更、备货状态和 BOL。
3. 为每个客户/收货地址生成带 Subject 的 T-1 再确认邮件。
4. 未取得第二次 OK 的项目不得标记最终放行。
5. 遇到临时换单，使用变更模板，原预约在客户确认前保持不变。

## 每周计划（周五 15:30 ET）

1. 汇总下周每日送货、工厂提货、回库、装箱和文件节点。
2. 标出时间冲突、同一车辆不合理排程、未确认备货、缺少 BOL/PL、未完成 T-1 复核等风险。
3. 输出下周总表和按天行动清单。

## 微信和附件安全边界

- 微信数据库路径只用于识别账户和附件根目录；不尝试解密或写入数据库。
- 微信界面读取必须是只读操作，且仅访问“库房”。
- 无法从界面确认来源的新附件只登记文件名、时间和大小，状态为 `Source Unverified`；不得打开或纳入计划。
- 配置中 `formalSources` 登记的文件可以直接读取。
- 能在“库房”群中逐字对应文件名的新附件登记到 `state.json` 的 `verifiedSources`，以后可作为正式来源读取。
- 不修改微信目录内的任何原文件。

## 输出目录

每次运行写入 `dispatch-assistant/outputs/YYYY-MM-DD/`，使用以下文件名：

- `daily-plan.md`
- `t1-confirmations.md`
- `weekly-plan.md`

同一天重复运行时更新同一文件，并在文件顶部保留生成时间和信息截止时间。所有邮件均为草稿。
